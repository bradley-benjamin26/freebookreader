## Context
- Layout: `gutendex/` (Django app, built and tested), `backend/` (FastAPI, built; all tests pass), `app/` (Flutter, built 2026-10-10; all 256 tests pass), `samples/` (captured API responses), `api_*.documentation.md` (one per API: Gutendex, LibriVox, Open Library, DOAB).
- Development is test-first. Tests exist for everything in `spec.md`; code should be written to make them pass. If a test needs to change, change it together with its README (`backend/tests/README.md`, `app/test/README.md`).
- Run the tests: `cd backend && source venv/bin/activate && python -m pytest`; `cd app && flutter test`; `cd gutendex && source venv/bin/activate && python manage.py test books --settings=gutendex.test_settings`.
- Gutendex runs locally on port 8001 (`python manage.py runserver 8001`) and uses Postgres. The Postgres role cannot create databases, which is why Django tests use SQLite.
- DOAB replaced OAPEN as a source (2026-10-10; source id `doab`). DOAB's REST API rejects our IP, so search = OpenSearch (`/open-search/discover`) + one OAI `GetRecord` (xoai) per hit; xoai's `oapenidentifierdownloadUrl` gives the PDF, usually in the OAPEN Library. OAPEN's site and PDFs are behind a bot check (403 to curl). DOAB is a joint service of OAPEN, OpenEdition, CNRS and Aix-Marseille Université (DOAB Foundation). Not decided: loading DOAB's nightly `DOAB.json` (324 MB, OPDS 2.0) into a local index instead, which would give a real language filter (see api_doab.documentation.md).
- Run the backend: `cd backend && source venv/bin/activate && uvicorn app.main:create_app --factory --port 8000` (settings: `FBR_*` env vars, see `backend/tests/README.md`). The top-level `.env` is JSON (`name`, `email`, `projectName`); the backend uses `projectName` and `email` for its User-Agent and never sends `name`.
- Outage rule: only the source's own errors (connection failure, 5xx, unreadable answer) take it out for 24 hours. Timeouts (user decision 2026-10-10), 4xx answers (`SourceRejected`) and crashes in our adapters leave it out of that search only. Search input is capped at 300 characters per field and page 1000; `language` is normalized to ISO 639-1 in `SearchQuery`.
- LibriVox: `author` = exact last name; `title` = exact full title (`^` = prefix); title+author together → HTTP 500 (backend sends `^title`, filters by author). Titles are stored without leading articles ("Time Machine"), so the backend strips them. Open Library: `q` needs 3+ chars; `lang` only boosts, undocumented `language=<MARC>` filters.
- Once the server's IP is known: email info@oapen.org asking them to allow it for DOAB's REST API and OAPEN's PDF downloads.
- Git (2026-10-10): one repo, branch `main`, pushed to github.com/bradley-benjamin26/freebookreader (private). License: MIT (`LICENSE`); `samples/` stays under the sources' terms. `gutendex/` is vendored from upstream commit 268b181; its original `.git` was moved to `../freebookreader-gutendex-upstream.git`. Secrets stay out of git: top-level `.env` (template `.env.example`) and `gutendex/gutendex/.env` (template `.env.template`). `gutendex/catalog_files/` (2 GB) is ignored.
- Flutter app (2026-10-10): `app/lib/` is built against the tests (292 pass). Off web, books show in our own text renderer (paragraphs from Gutenberg HTML, paginated with `TextPainter`). Not done yet: a bundled dyslexia-friendly font (that choice falls back to the platform font), EPUB off web, and a PDF viewer (`main.dart` links PDFs out). Platform folders (android, ios, web) exist and the app has been run successfully (2026-10-10). Packages: http, shared_preferences, url_launcher, just_audio, html, flutter_readium, pointer_interceptor (on web, anything Flutter draws over Readium's iframe must be wrapped in a `PointerInterceptor` or the iframe takes its clicks; see decision_reader.md check 7). Run: `cd app && flutter run --dart-define=BACKEND_URL=http://localhost:8000`. The first `flutter test` after adding native packages can fail writing `.dart_tool/hooks_runner`; running it again works.
- Backend code review 2026-10-10: `backend/REVIEW-2026-10-10.md`. #1–#8 all fixed 2026-10-10. #8: LibriVox author search drops a trailing Jr./Sr./II–VI; side issue also fixed: a suffix after a comma is not a given name ("Charles Dickens, Jr." → "Charles Dickens Jr."). #7: `sources` must name at least one source (`sources=,` → 422; blank = all); duplicates are dropped. #6: at most 4 searches per source run at once; a source with none free is skipped (not an outage). #4: a fuzzy author match needs identical given names; only the surname may be fuzzy. #5 decision: a title search matches with or without the subtitle (and volumes of the work), but never study guides or summaries. Update each finding's Status line there as it is fixed.
- Open merge questions (found in live searches 2026-10-10, not decided): Open Library works merge with each other through shared ISBNs, which pulls omnibus works ("Novels (Pride and Prejudice / Sense and Sensibility)") into the novel's work. The `gutenberg` cross-references from LibriVox and Open Library are not used for merging, so "Misérables - tome 1" (LibriVox, Gutenberg 17489) stays apart from Gutenberg 17489. Each Open Library work also carries hundreds of ISBNs, which makes `/search` responses 100–250 KB.
- Web reader (2026-10-10): `flutter_readium` on web needs a Readium manifest (EPUB profile) plus the book's files from one origin; it cannot open an .epub, and gutenberg.org has no CORS. The backend serves `/publications/gutenberg/<id>/manifest.json` and files (`app/publications.py`, disk cache `backend/cache/epub`). Spike app: `spikes/reader/` (run `flutter run -d web-server --web-port 8080`, then paste `http://localhost:8000/publications/gutenberg/1342/manifest.json`). `spikes/epub_server/serve.py` is the throwaway prototype. `/search` gives it as `reading.publication` (a path on the backend; null for other books), and the app's `ReadingOptions` reads it. Web TTS stalls in Chrome even on the first Start (default voice); try picking a local voice for the book's language.
- Reader: not decided. Spike `flutter_readium` first (see decision_reader.md). TTS is a goal. Offline downloads are allowed but unscheduled. Audio uses just_audio.
