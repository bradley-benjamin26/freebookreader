## Context
- Layout: `gutendex/` (Django app, built and tested), `backend/` (FastAPI, built; all tests pass), `app/` (Flutter, built 2026-10-10; all 445 tests pass), `samples/` (captured API responses), `api_*.documentation.md` (one per API: Gutendex, LibriVox, Open Library, DOAB, HathiTrust).
- Development is test-first. Tests exist for everything in `spec.md`; code should be written to make them pass. If a test needs to change, change it together with its README (`backend/tests/README.md`, `app/test/README.md`).
- Run the tests: `cd backend && source venv/bin/activate && python -m pytest`; `cd app && flutter test`; `cd gutendex && source venv/bin/activate && python manage.py test books --settings=gutendex.test_settings`.
- Gutendex runs locally on port 8001 (`python manage.py runserver 8001`) and uses Postgres. The Postgres role cannot create databases, which is why Django tests use SQLite.
- DOAB replaced OAPEN as a source (2026-10-10; source id `doab`). DOAB's REST API rejects our IP, so search = OpenSearch (`/open-search/discover`) + one OAI `GetRecord` (xoai) per hit; xoai's `oapenidentifierdownloadUrl` gives the PDF, usually in the OAPEN Library. OAPEN's site and PDFs are behind a bot check (403 to curl). DOAB is a joint service of OAPEN, OpenEdition, CNRS and Aix-Marseille Université (DOAB Foundation). Not decided: loading DOAB's nightly `DOAB.json` (324 MB, OPDS 2.0) into a local index instead, which would give a real language filter (see api_doab.documentation.md).
- Gutenberg edition details (2026-10-10): our vendored Gutendex adds `release_date`, `last_updated`, `credits`, `original_publication` to each book (migration 0006, parsed from the RDF in `books/utils.py`; upstream lacks them). The backend's `Book` has the same fields (null for other sources) and the details page shows them on each book card with the eBook number ("eBook #1342"), so several Gutenberg eBooks of one work can be told apart. `last_updated` = newest file under `/files/<id>/` (generated files are rebuilt monthly and ignored), null if not after release. After pulling: `manage.py migrate`, then `updatecatalog`.
- Run the backend: `cd backend && source venv/bin/activate && uvicorn app.main:create_app --factory --port 8000` (settings: `FBR_*` env vars, see `backend/tests/README.md`). The top-level `.env` is JSON (`name`, `email`, `projectName`); the backend uses `projectName` and `email` for its User-Agent and never sends `name`.
- Outage rule: only the source's own errors (connection failure, 5xx, unreadable answer) take it out for 24 hours. Timeouts (user decision 2026-10-10), 4xx answers (`SourceRejected`) and crashes in our adapters leave it out of that search only. Search input is capped at 300 characters per field and page 1000; `language` is normalized to ISO 639-1 in `SearchQuery`.
- LibriVox: `author` = exact last name; `title` = exact full title (`^` = prefix); title+author together → HTTP 500 (backend sends `^title`, filters by author). Titles are stored without leading articles ("Time Machine"), so the backend strips them. Open Library: `q` needs 3+ chars; `lang` only boosts, undocumented `language=<MARC>` filters.
- Open Library returns only books that can be read or borrowed now (user request 2026-10-10). `q` always ends with `ebook_access:[borrowable TO *]`, the result links the edition from the `editions` sub-query (`/books/OL…M`, not the work page), and one call to the undocumented `/availability/v2` drops editions on loan (`borrow_unavailable`) or without a scan (`error`). If that call fails, results are kept and it is not an outage. Trade-off: an ISBN search for an edition that cannot be borrowed finds nothing, even when another edition of that work can be borrowed.
- HathiTrust (decided and built 2026-10-11; `decision_hathitrust.md`, `api_hathitrust.documentation.md`): source id `hathitrust`, searched in a local SQLite FTS5 index of the Hathifiles (`access=allow` and `bib_fmt=BK` rows only), never live. Build/refresh: `cd backend && source venv/bin/activate && python -m app.hathitrust_update` (first run 1.2 GB, 4 min; index `backend/cache/hathitrust.sqlite`, 1.65 GB, 5.35 M volumes; `FBR_HATHITRUST_INDEX`). **Nothing schedules it yet** (examples in `backend/deploy/`: cron, systemd service + timer; untested on a server) and the index is not in git; without it the source is skipped (reason `error`). Code: `app/hathifile.py`, `hathitrust_index.py`, `hathitrust_update.py`, `sources/hathitrust.py`. A book is a volume (`volume`, `library`, `us_only` fields); one copy per record+volume label is listed; volumes of one catalog record merge through `identifiers.hathitrust`. `normalize_isbn` rejects the fake ISBN `9780000000002`. The reader host `babel.hathitrust.org` is blocked for our IP, so books link out (external); an in-app WebView/iframe waits for the checks in the decision file. Details page shows the first 3 volumes of a work and "Show all N HathiTrust volumes" (2026-10-11). Open: stopwords are now dropped from searches (measured 2026-10-11 on the real index, built on this machine: ordinary searches 0.01–0.6 s; a search of only stopwords finds nothing and is not run (user decision 2026-10-11; it took 5–10 s); one very common non-stopword about 2 s ("history"); end-to-end `/search` with `sources=hathitrust` works), nightly job. No donation link for HathiTrust (user decision 2026-10-11): `donation_url` is null, the About page shows only the website link.
