# UI review, 2026-11-18

Run against the web build in headless Chromium at 1280×800 and 390×844, light and dark (system setting). Path walked: Home → search → results → details → reader, plus audio, filters sheet, About, and a search with no results. The plan that fixes these is `docs/superpowers/plans/2026-11-18-ui-review-fixes.md`.

## Blocking use

1. **The reader ignores dark mode.** `ReaderSettings.theme` defaults to `light` whatever the system says, and the reader's app bar follows that setting, so a dark-mode user gets a bright white screen when they open a book.
   **Status:** fixed 2026-11-18: the reader's colours have a third choice, Auto (the default), resolved with the system brightness and followed while a book is open; a chosen Light or Dark stays.
2. **No covers on web.** `/search` returns `cover_url` (gutenberg.org), but gutenberg.org sends no CORS header and `Image.network` on CanvasKit needs one, so every cover is the placeholder.
   **Status:** fixed 2026-11-18: covers are drawn as `<img>` elements on web (`WebHtmlElementStrategy.fallback`); 64 px on cards. Checked with archive.org covers; gutenberg.org was down for maintenance (503), so its covers were not seen loading.
3. **Books open on Gutenberg's licence text** in the web reader (Readium starts at the first reading-order file, which holds the licence and the title page). The text renderer used off web already removes `#pg-header`.
   **Status:** fixed 2026-11-18: a new book opens at its first contents entry, and the backend cuts `#pg-header` out of served pages (Readium on web ignores a contents entry's fragment, and the header shares a file with the title page). The footer and licence stay.
4. **There's no progress or contents in the web reader.** The page controls ("N% read", Previous, Next) and the read-aloud bar are drawn but hidden (see 5), and there is no way to jump to a chapter.
   **Status:** fixed 2026-11-18: with #5 the page controls and the read-aloud bar show; a Contents button lists the table of contents and goes to an entry.
5. **The book covers the controls below it, and the play button is clipped.** Readium's bundled CSS sets `#wrapper{height:calc(100vh - 96px)!important}`, so the iframe ends 96px above the bottom of the window whatever space Flutter gave it. Measured: the iframe spans 56–760px on an 800px window and covers the page controls and the read-aloud bar.
   **Status:** fixed 2026-11-18: `app/web/index.html` overrides Readium's height (`#wrapper#wrapper { height: 100% !important; }`); `app/tool/check_reader_layout.mjs` checks it (OK at 1280×800 and 390×844).
6. **The details page and the result card disagree.** The card's button opens `work.bestBook` (a text), but the details page lists books in their own order (for Frankenstein the Gutenberg audiobook comes first).
   **Status:** fixed 2026-11-18: the details page lists the result button's book (`bestBook`) first.

## Accessibility

7. The single-choice chips ("Search in", Format) are announced as **checkboxes**. They should be radio buttons in a group (4.1.2).
   **Status:** fixed 2026-11-18: "Search in" is a dropdown (#11); the format chips are radio buttons (checked in the browser's accessibility tree).
8. **Every heading is level 2**, including the app name and page titles (1.3.1).
   **Status:** fixed 2026-11-18: page titles are level 1, sections level 2.
9. Key information is in 12px `bodySmall` text: the source list, "Read in this app.", the eBook number.
   **Status:** fixed 2026-11-18: result cards use `bodyMedium` or larger; the source list moved to the details page.

## Ease of use

10. **Result cards have 7–8 lines of equal weight**, so about 2 fit on a phone. Keep the which-copy line and the access note (persona round one); move the source list to the details page.
   **Status:** fixed 2026-11-18: cards show title, author, one facts line, the button, the which-copy line (one line) and the access note.
11. **The "Search in" chips take two rows on a phone.** Use one dropdown beside the search box.
   **Status:** fixed 2026-11-18: one dropdown before the search box, on its own line only when the bar is narrower than 320 px × the text scale.
12. **The desktop filter rail has no visible group labels** (Sources, Format, Language).
   **Status:** fixed 2026-11-18: the wide rail and the phone sheet show "Sources", "Format" and "Language".
13. **The details page leads with its weakest parts** (placeholder cover, then the offline note). Show the main button under the title and move the offline note to the end.
   **Status:** fixed 2026-11-18: the main button is under the title; the offline note is last.
14. **One author appears twice**, "Mary Wollstonecraft Shelley and Mary Shelley" (Gutenberg + Open Library merged; the backend keeps both spellings).
   **Status:** fixed 2026-11-18: when works merge, a shorter spelling from another record ("Mary Shelley") is dropped; names in one record are never folded.
15. **The audio player shows no times**, and the playing chapter is shown only by colour.
   **Status:** fixed 2026-11-18: time played and time left under the slider; the playing chapter has an icon ("Current chapter"). A recording of unknown length still shows "N played · length unknown".
16. **About (and Home) sit vertically centred**, leaving an empty band at the top on desktop.
   **Status:** fixed 2026-11-18: Home, About and details sit at the top. The audiobook page is still centred (not in this finding).
17. **Home spends its space on five "About …" rows**; the example books are small chips. Show the examples as covers and the sources as a compact row of links.
   **Status:** fixed 2026-11-18: the examples are covers with titles (placeholders while gutenberg.org is down); the sources are a row of links.

## Look

18. Use one reading serif for titles (Literata, OFL, bundled as an asset). Once covers load, make them larger on cards. Hold off on new colours.
   **Status:** fixed 2026-11-18: titles (headline, `titleLarge`, `titleMedium`) use Literata 3.103 (bundled, OFL); dropdowns keep the body font. Covers are 64 px on cards. No new colours.

## Left open (minor, found while fixing the above)

Found in the final self-review and the browser walk on 2026-11-18. None blocks use; not scheduled.

19. **Author order can shift after a merge.** When the text record has the shorter spelling ("Mary Shelley") and another record the longer one, the shorter is dropped where it stood and the longer stays where its record put it, so that author can move later in the list (`backend/app/merge.py`, `_work`).
20. **Two identical buttons on the details page.** The main button under the title (`open-primary`) and the first book card's button are both "Read <title> by <author>". A screen reader user hears the same button twice.
21. **The audiobook page is vertically centred**, leaving an empty band at the top on desktop (the same as #16, which named only Home and About).
22. **Scanned page images stay dark on dark in the dark reader.** Readium darkens the page but not images, so a scanned title page (Frankenstein, eBook #41445) is hard to see.
23. **The settings preview draws "Serif" in a sans font on web.** The reader's `serif` family has no matching font in CanvasKit, so the preview falls back to Roboto.
24. **The font size value ("18") in the settings sheet is in the title serif** (`titleMedium`), unlike the labels around it.
