## 1. Blocker: one user request can take a source offline for everyone for 24 hours

**Where:** `app/search.py:64-66` (any exception → `record_failure`), `app/sources/base.py:38`
(any status ≥ 400 → `SourceError`), `app/sources/librivox.py:65`, `app/main.py:32-41` (no input limits).

**What's wrong:** every failure counts as an outage, including crashes in our own adapter code and
4xx responses caused by our own requests. User input has no length or range limits.

**Reproduced:**
- `author=(anon)` or `author=(1812-1870)`: `normalize_author_name` returns `""`, so
  `"".split()[-1]` raises `IndexError` at `librivox.py:65`. LibriVox is then marked down for 24 h.
- `q` of 3,000 characters (`"history " * 375`): Open Library answers HTTP 500 and is marked down.
- `page=10**9`: Open Library answers HTTP 500 and is marked down. (`page=100000` is fine: Open
  Library really has ~4 million results for "history". DOAB, Gutendex and LibriVox return nothing
  past the end, which is correct.)

```python
from app.config import Settings, build_http_client, build_search_service
from app.models import SearchQuery
s = Settings.from_env({}); svc = build_search_service(s, build_http_client(s))
svc.search(SearchQuery(author="(anon)", sources=["librivox"]))
print(svc.outage.unavailable())   # ['librivox']
```

**Fix:**
- Limit input at the API: maximum lengths for `q`, `title`, `author`, `keyword` and `isbn` (a few
  hundred characters), and a maximum `page`. Reject anything beyond them with 422.
- Guard `librivox.py:65` against names that are empty after normalization: skip the request, or
  return `[]`.
- Count only failures that mean the source is broken as outages: connection errors, 5xx, and
  unreadable responses. An unexpected exception in our code, or a 4xx answer to our request, should
  fail that one search for that source (reported in `unavailable_sources`) without calling
  `record_failure`. This changes the outage rule, so update `spec.md` and the tests README too.

**Tests to add:**
- A parametrized test sending hostile inputs to every adapter (`(anon)`, `(1812-1870)`, a 3,000-character
  `q`, punctuation only, a huge page) and asserting each adapter returns a list or raises `SourceError`,
  never anything else.
- A search-service test showing that a non-`SourceError` exception (`RuntimeError`) does **not** start the
  outage. The existing `test_any_failure_counts_as_an_outage` asserts the opposite for `RuntimeError`, so
  change it together with the README.
- API tests: too-long fields and an over-large `page` return 422.

**Status: fixed 2026-10-10.** `SearchQuery` limits text fields to 300 characters and `page` to 1000
(`MAX_TEXT_LENGTH`, `MAX_PAGE`); the API answers 422 beyond them. LibriVox makes no request for an author
with no name left. A 4xx raises `SourceRejected`, and `SearchService` calls `record_failure` only for
other `SourceError`s; rejections and crashes in our code leave the source out of that search only.
Tests: `tests/test_hostile_inputs.py`, `TestOutages.test_our_own_failures_are_not_an_outage` (replaces
`test_any_failure_counts_as_an_outage`), new 422 cases in `test_api.py`, and limit tests in `test_models.py`.
`spec.md` and the tests README were updated. Re-ran the `(anon)` reproduction live: LibriVox stays available.

## 2. Should fix: language codes are not normalized

**Where:** `app/models.py:73-80` (`language` only stripped), with raw comparisons in
`app/sources/librivox.py:53`, `app/sources/doab.py:52` and `app/sources/openlibrary.py:55`
(sets `book.language = query.language` verbatim). Gutendex also receives the raw value.

**Reproduced** (live searches for `q=hugo`):

| `language=` | Books returned |
|---|---|
| `fr` | Gutenberg 31, Open Library 20, DOAB 3 |
| `FR` | Gutenberg 31 only (Open Library labelled `"FR"`, then dropped by the service filter) |
| `fre`, `French` | none at all |
| `klingon` | accepted, HTTP 200 |

**Fix:** in `SearchQuery`, convert `language` with `to_language_code` and raise a validation error
(422) when it is unknown. Then every adapter sees a 2-letter lowercase code.

**Tests:** `SearchQuery(language="FR").language == "fr"`, and the same for `fre` and `French`;
unknown → `ValidationError`; and an API test that `language=klingon` returns 422.

**Status: fixed 2026-10-10.** `SearchQuery` converts `language` with `to_language_code` and rejects unknown
values; `SearchService` no longer converts it again.

## 3. Should fix: Gutenberg books in more than one language are dropped from language searches

**Where:** `app/sources/gutendex.py:64` (`languages[0]`).

**Reproduced:** for `q=hugo&language=fr`, Gutendex returns 12137 "La Légende des Siècles"
(`languages: ["en", "fr"]`). It is labelled `en`, and the service's language filter drops it.

**Fix:** if `query.language` is in the record's `languages`, use it as the label. Otherwise keep
`languages[0]`.

**Test:** set a sample record's `languages` to `["en", "fr"]`, search with `language="fr"`, and assert the
book is returned with `language == "fr"`.

**Status: fixed 2026-10-10.** Live check: `q=hugo&language=FR` now returns 32 Gutenberg books (31 before),
including 12137 "La Légende des Siècles".

## 4. Should fix: fuzzy merging joins books by different people

**Where:** `app/merge.py:18` (`AUTHOR_SIMILARITY = 88`), `app/merge.py:116`.

**Reproduced** (`merge_books` on two books titled "Poems", same language):

| Authors | Similarity | Result |
|---|---|---|
| John Smith / Joan Smith | 90 | merged (wrong) |
| John Adams / John Addams | 95 | merged (probably wrong) |
| Mary Shelley / Mary Shelly | 96 | merged (right: a misspelling) |
| Thomas Hardy / Thomas Harding | 85 | separate |

The spec says a duplicate is better than a false merge.

**Fix ideas** (choose one, keeping `TestPass3Fuzzy` green, especially Dostoevsky/Dostoyevsky):
- Require the same number of name parts, and allow fuzziness only in the surname, with a high
  threshold (≥ 95).
- Or require an exact author key when the titles match exactly, and allow fuzzy authors only when
  the titles also differ only slightly.

**Test:** "Poems" by John Smith and by Joan Smith stay separate.

**Status: fixed 2026-10-10** (first idea, with surname threshold 90 rather than 95: at 95 the "right"
merge Mary Shelley/Mary Shelly, ratio 92, would be lost). `merge._same_authors` requires the same number of
authors, the same number of name parts and identical given names; only the surname is compared fuzzily
(`SURNAME_SIMILARITY = 90`, replacing `AUTHOR_SIMILARITY`). John/Joan Smith and Thomas Hardy/Harding stay
separate; Shelley/Shelly and Dostoevsky/Dostoyevsky merge. Known limit: John Adams/John Addams (surname
ratio 91) still merges; no string measure separates it from Shelley/Shelly. Transliterated given names
("Fyodor"/"Fedor") no longer merge, which the spec accepts as a duplicate. Tests: three new cases in
`TestPass3Fuzzy` (508 tests pass); decision added to the tests README.

## 5. Should fix, needs user decision: a title search must match the whole title, including any subtitle

**Where:** `app/search.py:84` (exact `title_key` equality).

**Reproduced:** title searches for "Moby Dick", "Les Misérables" and "Black Beauty" drop the
Gutenberg books "Moby-Dick; or, The Whale", "Les misérables Tome I: Fantine" and "Black Beauty: The
autobiography of a horse".

**Conflict:** `tests/test_search_service.py:110-125` deliberately excludes "Great Expectations: A Study
Guide" from a title search for "Great Expectations". Matching the part before `:` would break that
test.

**Question for the user** (do not change this until answered): should a subtitle count as the same
title?
- Option A: the main title (before `;`, `:` or " or") counts, so study guides come back too.
- Option B: as A, but a short list of subtitle words marks a different book ("Study Guide", "Notes",
  "Summary", ...).

**Status: fixed 2026-10-10, option B (user decision).** New `normalize.title_matches`, used by
`search._is_the_item`. A volume of the work also counts ("Les Misérables" finds "Tome I: Fantine"), and
leading articles in any language are ignored so LibriVox's "Misérables - tome 1" is found. Tests:
`TestTitleMatches` in `test_normalize.py` and two new `TestKnownItemSearch` tests; "Great Expectations: A
Study Guide" stays excluded. Live: "Moby Dick", "Les Misérables" and "Black Beauty" now return the Gutenberg
and LibriVox books listed above, and no study guides.

## 6. Consider: slow sources leave threads running

**Where:** `app/search.py:46-50` (a new `ThreadPoolExecutor` per search, `shutdown(wait=False)`).

**Reproduced:** with `FakeSource("doab", delay=2.0)` and `timeout_seconds=0.05`, 20 searches left
20 threads running. In production DOAB also starts up to 10 lookup threads each time (`doab.py:48`),
and a stuck DOAB search can run for about 45 s (one search plus two waves of lookups, each with
httpx's 15 s timeout). Because timeouts no longer pause a source (user decision 2026-10-10), a
slow source is asked again on every search, so the threads keep growing under load.

**Fix:** one shared, size-limited executor in `SearchService`; and/or skip a source that already has a
search in flight, reporting it in `unavailable_sources`.

**Status: fixed 2026-10-10** (both ideas, with a limit of 4 rather than 1, so that users searching at the
same time do not push each other out). Each source may have at most `MAX_IN_FLIGHT = 4` searches running;
a running search holds a slot until its thread really finishes, even after the response has gone. A source
with no free slot is not asked and is listed in `unavailable_sources`, without `record_failure`. Searches run
on one executor per `SearchService` (`sources × 4` workers), so a search never waits for a worker. The
reproduction above now leaves 3 threads with a limit of 3 (it left 20). Remaining bound: a stuck DOAB holds 4
searches, each with up to 10 lookup threads. Tests: `TestSearchesInFlight` in `test_search_service.py`.

## 7. Consider: `sources=,` is accepted as an empty selection

**Where:** `app/main.py:47`. `sources=,` becomes `[]`, so the search runs against no sources and
returns 200 with nothing. It should return 422 (add `min_length=1` to `SearchQuery.sources`, or treat
an empty list as `None`). `sources=doab,doab` passes the duplicate through; that's harmless, but it
could be de-duplicated.

**Status: fixed 2026-10-10** (both). `SearchQuery.sources` has `min_length=1`, so `sources=,` is 422; a missing or
blank `sources` still means all sources. Duplicates are dropped, keeping the first order. Tests: two new 422 cases
and `test_blank_sources_means_all_sources`, `test_duplicate_sources_are_dropped` in `test_api.py`;
`test_search_query_rejects_an_empty_source_selection` and `test_search_query_drops_duplicate_sources_keeping_order`
in `test_models.py` (520 tests pass).

## 8. Consider: LibriVox author search can send a name suffix

**Where:** `app/sources/librivox.py:65`. "Dickens Jr." sends `author=Jr.`, which finds nothing. Drop
common suffixes (Jr., Sr., II, III, ...) before taking the last word.

**Status: fixed 2026-10-10.** `librivox._NAME_SUFFIX` (`Jr`, `Sr`, `II`–`VI`, any case, optional dot) is dropped
from the end of the name before the last word is taken; a name that is only a suffix makes no request. Tests:
`test_name_suffixes_are_not_sent_as_the_last_name` and `test_a_suffix_alone_makes_no_request` in
`test_source_librivox.py` (529 tests pass). Live: "Charles Dickens Jr." now sends `author=Dickens` (25 books, all
dropped by the service's known-item filter, since none are by the son); "Martin Luther King Jr." sends `author=King`.
Side issue, also fixed 2026-10-10: `normalize_author_name("Charles Dickens, Jr.")` gave "Jr. Charles Dickens",
because it read the comma as "Last, First". A comma part that is a suffix (`Jr`, `Sr`, `II`–`VI`, at least two
letters, so "Smith, V." stays an initial) is now moved to the end instead of being taken as the given name, as is
a suffix at the end of the given name ("Dickens, Charles Jr."). "Charles Dickens, Jr." and "Dickens, Charles, Jr."
both give "Charles Dickens Jr."; Roman numerals stay uppercase. The suffix pattern moved to
`normalize.NAME_SUFFIX`, which LibriVox now imports. Tests: new cases in `test_normalize.py` (542 tests pass).

## Checked and fine (don't re-review)

- **Merging:** independent of input order; two languages never share a work, even through identifier
  chains; books with an unknown language merge only on ISBN or OCLC.
- **Deep pages:** DOAB, Gutendex and LibriVox return nothing past the end; Open Library's page 100000
  is real data.
- **Outage tracker:** thread safety and clock handling; `unavailable_sources` lists only selected
  sources.
- **Privacy:** log messages contain the endpoint, not the user's query; the `.env` name is never sent.
- **CORS `*`** is acceptable for a public read-only API with no credentials.
- **XML parsing** with `xml.etree` is acceptable for now: the bundled expat resists entity-expansion
  attacks, and the XML comes from DOAB only. Revisit if more XML sources are added.

## Done well

- Adapters are tested against real captured responses, and each live quirk became a test plus a
  documented decision.
- Merging is truly independent of input order.
- Errors, timeouts and "no results" (LibriVox's 404, Open Library's 422, DOAB's stale entries) are
  each handled on purpose.

## Habit to build

Before handling an error, decide whose fault it is: the user's input, our own code, or the external
source. Only the source's fault should affect other users. Most of #1 comes from treating all three
the same way. Keep a short list of hostile inputs and test every input path against it.
